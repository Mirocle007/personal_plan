# 个人规划中心 v2.0 — 技术方案（技术确认）

> 版本：v2.0 ｜ 日期：2026-09-19

## 1. 总体架构

延续前后端分离单体架构，**降低复杂度优先**（个人本地工具，不引入微服务/中间件）：

```
┌─ frontend/  React 19 + Vite + Tailwind v4 (SPA)
│    dev: 5173 (vite proxy → 3001)   prod: 静态文件由后端托管
├─ backend/   Express 5 + Sequelize + SQLite (CommonJS + ts-node)
│    api: 3001/api/*   prod: 3001/* 同时服务 SPA
└─ 数据: backend/database.sqlite（运行时文件，不入 git）
```

## 2. 技术选型与依赖变更

### 后端（保留）
- Express 5、Sequelize 6、sqlite3、TypeScript、nodemon + ts-node。
- 新增：无（用 Node 内置能力足够）。

### 前端
| 依赖 | 变更 | 理由 |
|---|---|---|
| lucide-react | **新增** | 统一图标体系 |
| recharts | **新增** | 仪表盘趋势图 / 报告分布图 |
| @dnd-kit/core + @dnd-kit/sortable | **新增** | 看板拖拽（轻量、无障碍友好） |
| date-fns | **新增** | 日期分组/日历网格计算 |
| react-quill | **移除** | v1 装而未用，且与 React 19 兼容差；描述改用纯文本 |
| jspdf | **移除** | 默认字体中文乱码；PDF 改为打印样式页 + `window.print()` |
| xlsx | 保留 | Excel 导出中文无问题 |

状态管理：不引入 Redux/TanStack Query。自建轻量层：`api.ts` 封装 fetch（统一 baseURL/错误检查/JSON 解析）+ 各页面 hooks。全局状态仅主题与 Toast，用 Context。

## 3. 数据模型（变更点）

```
Project   + color STRING(默认调色板色)
Task      + tags TEXT(JSON 数组)   + completedAt DATE(NULL)
          + order INTEGER(看板排序, 默认0)
SubTask   新表: id, taskId(FK, CASCADE), title, done BOOL, order
Habit     新表: id, name, icon(emoji), frequency('daily'|'weekly'), weeklyTarget INT
HabitRecord 新表: id, habitId(FK, CASCADE), date TEXT('YYYY-MM-DD', UNIQUE habitId+date)
ProgressUpdate / 备份模块：结构不变
```

- 同步策略：`sequelize.sync({ alter: true })` — 保留 v1 数据，自动加列/建表。
- **修复 v1 缺陷**：Task→ProgressUpdate 增加 `onDelete: 'CASCADE'`；备份文件名白名单校验（禁 `..`/`/`/`\`）。

## 4. API 设计（v2）

统一前缀 `/api`，统一错误结构 `{ error: string }`，新增全局错误中间件。

```
GET/POST       /tasks                    支持 ?search&status&priority&projectId&tag&dueFrom&dueTo&sort&order
GET/PUT/DELETE /tasks/:id
POST           /tasks/:id/complete       切换完成（写 completedAt）
GET            /tasks/:id/subtasks
POST           /subtasks                 {taskId,title}
PUT/DELETE     /subtasks/:id
GET/POST       /projects   GET/PUT/DELETE /projects/:id   （项目含任务统计聚合）
GET            /dashboard                一次性聚合：今日待办/即将到期/统计卡/7天趋势/项目进度
GET/POST       /habits     PUT/DELETE    /habits/:id
POST           /habits/:id/check         打卡/取消当日
GET            /habits/:id/records?days=30
POST           /summaries/generate       （修复：按项目名 join）
GET/POST       /backups  POST /backups/:name/restore  DELETE /backups/:name
```

删除端点均级联清理子数据；所有写入做枚举/类型校验。

## 5. 前端架构

```
frontend/src/
├─ api/client.ts          fetch 封装（baseURL、错误抛出、类型化）
├─ constants.ts           状态/优先级/颜色枚举（前后端口径一致）
├─ hooks/                 useTheme / useToast / useApi(轮询刷新) / useKeyboard
├─ components/ui/         Button Card Badge Modal ConfirmDialog Select Input
│                         Toast Skeleton EmptyState ProgressDot …（自建设计系统）
├─ components/task/       QuickAdd(自然语言解析) TaskCard TaskDetailPanel(侧滑)
│                         TaskFilters / parser.ts(NL 解析器)
├─ components/layout/     Sidebar(可折叠+高亮) Topbar(搜索+主题+新建) AppShell
├─ pages/                 Dashboard Tasks(列表/看板/日历/四象限四视图合一)
│                         Projects Habits Focus(番茄钟) Summary Backup Settings NotFound
└─ theme.css              CSS 变量双主题 + Tailwind v4 @theme 映射
```

- **视觉规范**：Inter 字体；主色 indigo→violet 渐变点缀；圆角 xl；卡片浅阴影；状态色（成功 emerald/警示 amber/危险 rose）；深色模式用 `class` 策略 + CSS 变量双份取值；过渡动画 150–200ms。
- 主题持久化 `localStorage`，跟随系统用 `prefers-color-scheme` 监听。

## 6. 自然语言解析器（frontend，无后端依赖）

规则按序扫描并从文本中剔除：
1. `!1|!2|!3` 或 `p1|p2|p3` → 高/中/低优先级
2. `#xxx` → 项目名（模糊匹配现有项目，无匹配则忽略）
3. `@xxx` → 标签（可多个）
4. 日期：`今天|明天|后天|大后天|下周[一二…日]|周[一二…日]|N月N日|YYYY-MM-DD|M-D|12-25`；`每天`不解析为重复（v2 不做重复任务）

## 7. 测试方案

1. **API 自动化**：`backend/test/api.test.mjs`（Node 内置 `node:test` + fetch），先备份生产库→用临时库跑全端点用例（CRUD/校验失败/级联/聚合/备份安全）→恢复。CI 可跑：`npm test`。
2. **类型/构建**：`tsc --noEmit`（前后端）、`eslint`、`vite build`。
3. **GUI 测试**：browser-use 黑盒走查十项验收标准中的交互项（快速添加/拖拽/主题/弹层/表单）。
4. **回归**：v1 的 test-regression.ps1 场景全部纳入 api.test.mjs 后退役。

## 8. 部署方案

- **开发**：`start.bat`（现状保留，修 front-end 启动参数）。
- **生产（Windows）**：`build.bat` 构建双端 → `start-prod.bat` 以 `NODE_ENV=production` 启动 Express 托管 SPA（单端口 3001）。
- **容器**：`Dockerfile`（多阶段：node 构建 → node:22-alpine 运行，数据卷挂 /app/data）+ `docker-compose.yml`。
- 健康检查端点 `GET /api/health`。

## 9. 版本管理策略

- 分支 `refactor/v2` 上按里程碑提交（conventional commits）：docs → backend → ui-framework → tasks → views → pages → tests → deploy，`--no-ff` 合回 `main`，打 `v2.0.0` 标签。
- 运行时数据（sqlite/backups）移出版本库，改为 `.gitignore` 管理。
